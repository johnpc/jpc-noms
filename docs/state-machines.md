# State machines

Every mode / phase / status in Noms, where it is written, and how it is tested.
**One mode, one owner:** a discriminated union (or enum) is written in ONE file;
everything else derives from it. `scripts/check-state-machines.mjs` (in
`npm run quality`, husky and CI) cross-checks this table against
`// @state-machine <id>` markers in the owner files, both ways, and refuses new
parallel `busy`/`error` booleans, `useRef(false)` consume-flags or `setTimeout`
sleeps in `src/` unless the file is cited here with a reason.

## Why this exists

The 2026-11-16 survey found ~20 implicit machines: the same `busy`+`error`
try/catch in five hooks, six pages deciding signed-out / loading / empty in
nested JSX ternaries (two of them flashing an empty state before the first
load), a 1.5 s `setTimeout` in Settings hoping an APNs token "had landed", a
`useRef(false)` one-shot guard, "decided" computed two different ways, and a
failed restaurant search rendered as "No restaurants found". All are now rows
below.

## Deliberately NOT machines (a boolean is the right tool)

Two-state, single-owner, purely local UI toggles — listed so nobody "fixes" them:

- `src/features/noms/NomOptionCard.tsx` `open` — collapsed/expanded row.
- `src/features/stats/HistoryRow.tsx` `open` — "other options" disclosure.
- `src/features/pairing/QrCode.tsx` `dataUrl` — '' until the QR encodes.
- `src/features/search/useGeolocation.ts` — default → stored → device fix; the
  app never shows WHICH, so a union would be unread. Cited here so the catalog
  gate accepts its plain state.
- react-query's own `isPending` per mutation (`inviting`, `accepting`,
  `unpairing`, `creating`, `busy` in `useNomActions`) — owned by the library.

## Known gaps (honest, not hidden)

- The fake backend emits subscription events only within one tab; two tabs do
  not see each other live (the real AppSync path does).
- `noms-history-load` is module state keyed by sub; a sign-out then sign-in as
  the SAME user within one session keeps the loaded flag (correct) but a
  garbage-collected cache is re-paged by the `prev.length === 0` check, not by
  the machine itself.
